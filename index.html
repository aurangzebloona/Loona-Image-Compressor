Develop a professional, advanced, and highly functional web application called **“Loona Image Compressor”**. Build the application as a **fully self-contained client-side web app** using only **HTML, CSS, and vanilla JavaScript**. Do not require a backend, database, server, API key, paid service, or manual code updates after deployment. ### 1. Core Purpose Create a powerful image compression tool that allows users to upload images, compress them with adjustable quality settings, preview the results, compare original and compressed images, and download the optimized files easily. ### 2. Supported Image Formats Support the following major formats wherever browser capabilities allow: * JPG / JPEG * PNG * WebP * GIF * SVG Clearly indicate when a format has browser-specific limitations. For animated GIFs, preserve animation whenever technically possible. Do not silently convert an animated image into a static image. For SVG files, provide safe optimization/minification without executing embedded scripts or unsafe content. ### 3. Modern User Interface Create a clean, modern, professional, responsive interface with: * Application name: **Loona Image Compressor** * Attractive header and branding * Large drag-and-drop upload area * “Choose Images” button * Multiple-image upload support * Upload progress/status indicators * Image preview thumbnails * File name, format, dimensions, and original file size * Responsive design for desktop, tablet, and mobile * Clear success, warning, and error messages * Accessible buttons, labels, and keyboard navigation Use a professional visual design rather than a basic demo-style interface. ### 4. Drag-and-Drop System Users must be able to: * Drag images into the upload area * Drop multiple images simultaneously * Select multiple images through the file picker * Remove individual files before compression * Clear the entire queue * Prevent unsupported files from being processed * Display useful validation messages ### 5. Compression Controls Provide precise user controls including: * Compression quality slider: 10–100 * Preset options: * Maximum Compression * Balanced * High Quality * Custom * Target output format where conversion is supported * Optional maximum width * Optional maximum height * Resize percentage * Maintain aspect ratio toggle * Metadata removal option * Transparent-background preservation where applicable Show the selected compression settings clearly before processing. ### 6. Image Processing Perform compression primarily on the user's device using browser-based APIs such as: * Canvas * OffscreenCanvas where supported * File API * Blob API * ImageBitmap where supported Avoid unnecessary server uploads so that users can process private images locally. The application should: 1. Read the selected image. 2. Validate the file. 3. Decode it safely. 4. Apply resizing if requested. 5. Apply compression according to the selected quality. 6. Generate the optimized output. 7. Calculate the new file size. 8. Calculate percentage size reduction. 9. Display the compressed preview. 10. Provide a reliable download option. ### 7. Before-and-After Comparison For every processed image, display: * Original preview * Compressed preview * Original file size * Compressed file size * Percentage saved * Original dimensions * Final dimensions * Output format Provide an easy visual comparison between the original and optimized image. ### 8. Background Removal Include an optional **“Remove Background”** feature. The architecture should allow background removal to work through a browser-compatible local processing approach where technically possible. Important: * Do not falsely claim professional AI background removal if no actual background-removal model is included. * If a local AI model/library is required, clearly structure the application so the feature can use it without exposing private images unnecessarily. * If true background removal cannot be implemented reliably with only native browser APIs, disable the feature gracefully and explain the limitation instead of providing a fake result. ### 9. Image Enhancement Include an optional **“Enhance Image”** feature with controls such as: * Brightness * Contrast * Sharpness * Saturation * Exposure Allow users to preview enhancement changes before applying them. Use lightweight browser-side processing where possible. ### 10. Batch Compression Support processing multiple images in one session. For each file show: * Processing status * Progress * Original size * Compressed size * Savings percentage * Success/error state Include: **Compress All** and, when practical: **Download All** For multiple downloads, create a ZIP file entirely in the browser if an appropriate self-contained client-side library is available. Otherwise provide individual download buttons. ### 11. Reliable Download System Every processed image must have a working download mechanism. Include: * Download button for each image * Correct file extension * Correct MIME type * Meaningful output filename * Download All option where possible * No broken blob URLs * Proper cleanup of temporary object URLs Example: `photo.jpg` → `photo-compressed.webp` ### 12. Privacy and Security The application should be designed with privacy and security in mind. Requirements: * Process images locally whenever possible. * Do not upload images to external servers by default. * Do not collect personal information. * Do not use unnecessary tracking scripts. * Sanitize SVG input before rendering it. * Never execute scripts contained inside uploaded SVG files. * Validate file types and file sizes. * Handle corrupted or unsupported files gracefully. * Avoid unsafe use of `innerHTML`. * Revoke temporary object URLs when they are no longer needed. ### 13. Performance Optimize the application for normal desktop and mobile browsers. Use: * Lazy processing where appropriate * Efficient memory management * Object URL cleanup * Asynchronous processing * Web Workers where beneficial * Non-blocking UI during large image processing Do not freeze the interface while processing large files. ### 14. Error Handling Provide user-friendly error messages for: * Unsupported format * Corrupted image * File too large * Browser limitation * Compression failure * Memory limitations * Background-removal failure * Download failure The application must never crash because of one invalid image. ### 15. Dashboard Statistics Display useful session-level statistics such as: * Number of images processed * Total original size * Total compressed size * Total storage saved * Average compression percentage Update these values automatically after processing. ### 16. Responsive Design The application must work smoothly on: * Desktop * Laptop * Tablet * Mobile phone Use responsive CSS with an intuitive mobile layout. ### 17. Accessibility Follow good accessibility practices: * Semantic HTML * Proper labels * Keyboard navigation * Visible focus states * ARIA attributes where appropriate * Sufficient contrast * Accessible error messages * Buttons with clear text ### 18. Code Architecture Keep the project clean and maintainable. Separate the code logically into: * HTML structure * CSS styling * JavaScript application logic Use clear functions/modules for: * File validation * Upload handling * Image decoding * Compression * Resizing * Enhancement * Background removal * Preview generation * Statistics * Download handling * Error handling Use descriptive variable and function names and meaningful comments only where necessary. ### 19. No Fake Functionality This is extremely important. Do not create buttons that only look functional. Every visible feature must either: 1. Work correctly in the browser, or 2. Be clearly marked as unavailable because the required technology is not present. Do not simulate compression percentages, fake AI processing, fake progress, or fake download results. ### 20. Self-Contained Requirement The final application should be capable of running by opening the HTML file directly or deploying it as a static website. Avoid unnecessary external dependencies.
